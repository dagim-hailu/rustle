# Wire protocol

Two protobuf contracts are checked in:

- [`proto/chat.proto`](../proto/chat.proto) — public browser ↔ Elixir gateway frames over a native WebSocket.
- [`proto/shield.proto`](../proto/shield.proto) — internal API ↔ Rust read shield gRPC.

The browser never sends JSON over the WebSocket. Each WebSocket binary message is exactly one encoded `chat.v1.ClientFrame` (or `ServerFrame` in the other direction). WebSocket message boundaries carry framing; there is no extra length prefix.

The SPA imports static code generated by `pbjs`/`pbts`, configures `long` so 64-bit fields remain strings, and uses `toObject(..., { longs: String, enums: String, oneofs: true, arrays: true })`. Static codegen is required because the production CSP forbids `new Function`.

## Connection lifecycle

```
TCP/WebSocket open
  └─ client sends Authenticate within 10s
       ├─ success: Authenticated + PresenceSnapshot
       └─ failure: AUTH_FAILED / AUTH_TIMEOUT + close 1008
  └─ client sends Subscribe(channelIds)
  └─ client increments presence with Heartbeat every 15s
  └─ server sends Message / PresenceEvent / TypingEvent / Pong / MessageAck
  └─ idle socket or missing heartbeat → close 4001
  └─ slow mailbox → close 1013
```

The auth token is inside the first protobuf frame, not a URL query parameter.

## ClientFrame

```proto
message ClientFrame {
  string request_id = 1;
  oneof payload {
    Authenticate authenticate = 2;
    Subscribe subscribe = 3;
    Unsubscribe unsubscribe = 4;
    SendMessage send_message = 5;
    Heartbeat heartbeat = 6;
    SetPresence set_presence = 7;
    Typing typing = 8;
    JoinCall join_call = 9;
    LeaveCall leave_call = 10;
    CallSignal call_signal = 11;
    CallMedia call_media = 12;
  }
}
```

| Payload | Important fields | Server behavior |
| --- | --- | --- |
| `Authenticate` | `token`, `client_version` | Verify JWT, fetch session, register connection, start presence. |
| `Subscribe` | repeated `channel_ids` | Membership-checked; max 100 ids per frame; idempotent. |
| `Unsubscribe` | repeated `channel_ids` | Removes local ETS routes. |
| `SendMessage` | `channel_id`, `content`, `attachments`, `client_id` | Validate, idempotency-reserve, persist, publish, ack. |
| `Heartbeat` | `status` | Refresh session/presence TTLs; returns `Pong`. |
| `SetPresence` | `status` | Same TTL refresh but an explicit status action. |
| `Typing` | `channel_id`, `active` | Ephemeral core NATS event; throttled server-side to one per second per connection. |
| `JoinCall` | `channel_id`, `video`, `muted`, `deafened` | Join a voice channel call; writes an ephemeral KeyDB roster entry and returns `CallSnapshot`. |
| `LeaveCall` | `channel_id` | Remove the roster entry and broadcast `CALL_EVENT_TYPE_LEAVE`. |
| `CallSignal` | `channel_id`, `target_session_id`, `type`, `sdp`/`candidate` | Target-routed `OFFER`/`ANSWER`/`ICE` relay. |
| `CallMedia` | `channel_id`, `video`, `muted`, `deafened`, `screen_sharing` | Update call media flags and broadcast `CALL_EVENT_TYPE_MEDIA`. |

Authentication is mandatory. Any other payload received before auth gets `AUTH_REQUIRED` followed by a 1008 close.

### SendMessage validation

- channel must be a UUID in the authenticated session;
- channel must be `text`;
- `content` ≤ 4000 Unicode characters;
- content or at least one attachment required;
- ≤ 10 attachments, each ≤ 2048 bytes, and each either `http(s)://` or `/uploads/...`;
- `client_id` must be 1–20 decimal digits (the temporary Snowflake string).

Attachments may reference images or audio/video files uploaded through `/api/uploads?kind=image|audio|video`. The API applies magic-byte checks and a 25 MiB default cap; the browser records audio/video with MediaRecorder and caps clips at two minutes.

No client-supplied message id is trusted or persisted as authoritative.

## ServerFrame

```proto
message ServerFrame {
  string request_id = 1;
  oneof payload {
    Authenticated authenticated = 2;
    ChatMessage message = 3;
    MessageAck ack = 4;
    PresenceEvent presence = 5;
    PresenceSnapshot presence_snapshot = 6;
    ServerError error = 7;
    Pong pong = 8;
    TypingEvent typing = 9;
    CallSnapshot call_snapshot = 10;
    CallEvent call_event = 11;
  }
}
```

### ChatMessage

| Field | Meaning |
| --- | --- |
| `id` (int64) | Authoritative Snowflake. On the wire int64; in JS use `long`/string. |
| `channel_id`, `guild_id`, `author_id` | UUID strings. |
| `author_name`, `author_color`, `author_avatar_url` | Denormalized presentation for immediate fan-out. |
| `content`, `attachments` | Message body and media refs. |
| `timestamp_ms` | Derived from the Snowflake, epoch milliseconds. |
| `client_id` | Echo of the browser's optimistic id for reconciliation. |

### User and member profiles

`User` and `GuildMember` carry `avatar_url`, `bio`, `pronouns`, `banner_url`, `banner_color` and `created_at` alongside the original id/name/color/presence fields. These fields are populated from PostgreSQL through the internal session snapshot; profile writes are HTTP/JSON (`PATCH /api/me/profile`) rather than WebSocket mutations.

### Calls

```proto
message CallParticipant {
  string session_id = 1;
  string user_id = 2;
  string display_name = 3;
  string avatar_url = 4;
  string avatar_color = 5;
  bool video = 6;
  bool muted = 7;
  bool deafened = 8;
  bool screen_sharing = 9;
}

message CallSnapshot {
  string channel_id = 1;
  string self_session_id = 2;
  repeated CallParticipant participants = 3;
}

message CallEvent {
  string channel_id = 1;
  string from_session_id = 2;
  string from_user_id = 3;
  string from_display_name = 4;
  string from_avatar_url = 5;
  string from_avatar_color = 6;
  string target_session_id = 7;
  CallEventType type = 8;
  string sdp = 9;
  string candidate = 10;
  bool video = 11;
  bool muted = 12;
  bool deafened = 13;
  bool screen_sharing = 14;
}
```

The roster is ephemeral in KeyDB. The gateway publishes `CallEvent` frames on `call.channel.<channel_id>`; each gateway routes them only to local sockets that joined that call. Events with a non-empty `target_session_id` are delivered to one participant; join/leave/media events broadcast. `CallSnapshot` is sent only to the joining connection. The SPA's `RTCPeerConnection` media path uses a default STUN server and optional TURN build settings; SDP/ICE bytes never pass through ScyllaDB or NATS JetStream (only core NATS signaling).

### MessageAck

| Field | Meaning |
| --- | --- |
| `channel_id`, `client_id` | Correlation. |
| `message_id` | Authoritative ScyllaDB Snowflake on success; `0` on failure. |
| `status` | `ACK_STATUS_COMMITTED` or `ACK_STATUS_FAILED`. |
| `timestamp_ms` | Authoritative timestamp on success. |
| `error`, `retryable` | Human-readable failure context and retry hint. |

The client timeout is **12 seconds**. On timeout, socket close, or a failed ack, the optimistic row becomes `FAILED`; retry resends the same `client_id` so the gateway can return the original authoritative id.

### Presence

Status enum:

```
PRESENCE_STATUS_UNSPECIFIED = 0
PRESENCE_STATUS_ONLINE = 1
PRESENCE_STATUS_IDLE = 2
PRESENCE_STATUS_DO_NOT_DISTURB = 3
PRESENCE_STATUS_OFFLINE = 4
```

The browser sends enum fields as **numeric wire values** (for example `{setPresence: {status: 3}}`). `protobufjs`'s `create()` does not resolve enum-name strings reliably and would otherwise silently produce `UNSPECIFIED`. Inbound frames are converted to enum-name strings with `toObject(..., {enums: "String"})`. The protocol test asserts that DND round-trips as value 3.

The SPA uses checked-in static code generated by `pbjs`/`pbts` (`web/src/lib/chat.generated.*`) rather than reflecting `chat.proto` at runtime. This avoids protobufjs codegen's `new Function`, which the production nginx `script-src 'self'` CSP blocks. Regenerate with `cd web && npm run proto:generate` after changing the protocol.

- `PresenceSnapshot` is sent on authentication, after `Authenticated`. It contains one event per guild/member pair.
- `PresenceEvent` subjects are `presence.guild.<guild_id>.user.<user_id>`.
- Heartbeat statuses may be `ONLINE`, `IDLE`, `DO_NOT_DISTURB`; `OFFLINE` is controlled by the server lifecycle/TTL and is rejected from heartbeats.
- UI automatic idle after 60s of no pointer/keyboard activity, when the current status is `ONLINE`. Any new activity sends `ONLINE`. `DND` is manual and is not overridden by activity.

### Errors

`ServerError { code, message, retryable }` codes include:

- `INVALID_FRAME`, `BINARY_REQUIRED`
- `AUTH_REQUIRED`, `AUTH_FAILED`, `AUTH_TIMEOUT`, `ALREADY_AUTHENTICATED`
- `INVALID_STATUS`, `CHANNEL_FORBIDDEN`
- `RATE_LIMITED`
- `PRESENCE_UNAVAILABLE`
- `CALL_UNAVAILABLE`, `CALL_FULL`, `CALL_SIGNAL_FAILED`, `CALL_MEDIA_FAILED`, `NOT_IN_CALL`
- `INTERNAL`

Ack failures are delivered as `MessageAck` rather than `ServerError` so the optimistic row can be reconciled even if a generic error toast occurs.

## Snowflake encoding

Implemented identically in Elixir (`Gateway.Snowflake`), Rust (`shield/src/ids.rs`) and TypeScript (`web/src/lib/snowflake.ts`):

```
| 41 bits milliseconds since 2024-01-01T00:00:00Z | 10-bit node | 12-bit sequence |
```

- positive 64-bit values, usable as Scylla blob via 8-byte big-endian;
- the gateway node id comes from `GATEWAY_NODE_ID` and must be unique across live gateways;
- browser temporary ids use the same layout with a random browser-local node and are only used as `clientId` / local display key; they are never accepted as a stored message id;
- ordering by big-endian bytes matches numeric Snowflake ordering.

Pagination cursors cross the HTTP API as decimal strings. The API sends fixed-width 8-byte cursors to the shield. The SPA compares ids with `BigInt`, never `Number`.

## Internal gRPC contract

[`proto/shield.proto`](../proto/shield.proto):

```proto
service ReadShield {
  rpc GetHistory(GetHistoryRequest) returns (GetHistoryResponse);
}

message GetHistoryRequest {
  bytes channel_id = 1;
  bytes before_message_id = 2; // empty = newest page
  uint32 limit = 3;
}

message GetHistoryResponse {
  repeated StoredMessage messages = 1; // newest first
  bytes next_cursor = 2;
  bool has_more = 3;
}
```

Validation:
- channel id exactly 16 bytes;
- before cursor empty or exactly 8 bytes;
- limit 1–100 (the UI/API uses 50).

The shield has no auth of its own in local Compose; it must run on a private network behind the API in production.

## Idempotency and acknowledgement edge cases

1. **Ack arrives before fan-out**: store commits the pending row from the ack; the later `ChatMessage` updates the same id.
2. **Fan-out arrives before ack**: store matches `clientId`, replaces the pending row with the committed id; a later ack is a no-op/reconcile.
3. **Retry after timeout, first attempt actually committed**: KeyDB returns the original Snowflake, gateway republishes, second ack commits.
4. **Duplicate fan-out** (at-least-once redelivery): store deduplicates by authoritative id.
5. **Out-of-order network arrival**: batching sorts by timestamp then Snowflake id, so visual order is deterministic.
6. **Gateway closes during a send**: all pending sends are marked `FAILED`; retry can recover via idempotency.

## Error and close codes

| Code | Meaning |
| --- | --- |
| 1003 | Text frame received where binary is required. |
| 1008 | Authentication/authorization failure. |
| 1013 | Slow consumer mailbox cap. |
| 4001 | Server heartbeat watchdog timeout. |
| 4002 | Client-side auth completion timeout. |

The browser uses exponential backoff with jitter (1s base, 15s cap) and re-authenticates on reconnect. On reconnection it resubscribes all text channels and refreshes the active channel's newest history to fill any gap.
